# IH-030 验证记录

## 修复内容

`intel-hidpi.sh` 的 `payload_dimensions` 原先使用 `xxd -p -c 100`，解码数据超过 100 字节时会
插入换行，随后十六进制校验会把合法 payload 判为无效。本任务在校验前通过 `tr -d '\n'` 去除
该格式换行，保留 Base64 解码失败的非零状态和原有最小长度、十六进制字符校验。

`tests/test_intel_hidpi_inventory.sh` 新增 104 字节合法 payload fixture，端到端断言 inventory
输出 `1920x1080 (104-byte payload)`。

## 验证命令

```text
/bin/bash -n intel-hidpi.sh tests/test_intel_hidpi_inventory.sh
TERM=xterm-256color /bin/bash -c 'shellcheck -x -s bash hidpi.sh hidpi.command intel-hidpi.sh lib/*.sh tests/test_hidpi_safe_entrypoint.sh tests/test_intel_hidpi_*.sh'
/usr/bin/swiftc -typecheck lib/intel_hidpi_runtime_modes.swift
git diff --check
/bin/bash tests/test_intel_hidpi_inventory.sh
for test_script in tests/test_*.sh; do /bin/bash "$test_script"; done
```

上述命令均退出码 `0`。完整串行 fixture 套件最终输出 `FULL_FIXTURE_SUITE=PASS`，共 11 项；
长 payload、非法 Base64 和短 payload 边界均已独立验证。所有测试写入均位于 `mktemp` 临时目录，
没有使用 `sudo`、没有写入系统 Overrides，也没有执行真实显示器操作或显示服务重载。

## 结论

长 payload 解码边界已修复，短 payload 和失败输入的既有行为保持不变，IH-030 验收标准满足。
