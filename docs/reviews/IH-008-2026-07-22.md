# IH-008 验证记录

## 范围

将每个 manifest 绑定到规范化的 override 根，并将协作中的单显示器锁命名空间从 `state-root`
移动到规范化的 override 根。

- manifest 版本 2 记录 `overrides-root`，回退会在计算哈希、删除或恢复目标前比较该字段；
- 版本 1 manifest 被显式拒绝，因为无法证明 override 根身份；
- 锁路径由规范化 override 根、vendor ID 和 product ID 推导。因此使用不同 `state-root` 的调用
  仍会串行访问同一个目标 override；
- 本次调用创建的隐藏锁目录会在锁释放时删除，前提是该目录为空。

## 自动验证

以下命令均以退出码 0 完成：

```sh
bash tests/test_intel_hidpi_inventory.sh
bash tests/test_intel_hidpi_preview.sh
bash tests/test_intel_hidpi_apply_revert.sh
bash tests/test_intel_hidpi_menu.sh
bash -n intel-hidpi.sh lib/intel_hidpi_storage.sh \
  tests/test_intel_hidpi_apply_revert.sh
shellcheck -s bash -x -P "$PWD" intel-hidpi.sh \
  lib/intel_hidpi_storage.sh tests/test_intel_hidpi_apply_revert.sh
git diff --check
```

apply/revert fixture 覆盖：

- manifest 版本 2 和规范化根字段；
- 使用不同 override 根的 manifest 被显式拒绝，同时保留该根的目标和原始 manifest；
- 没有改变目标或状态的情况下显式拒绝缺少根字段的版本 1 manifest；
- 后台操作锁会阻止对同一目标执行使用不同 state 根的 apply。

本任务没有向 `/Library/Displays` 或 `/Library/Application Support` 写入任何内容。
