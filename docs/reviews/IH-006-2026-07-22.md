# IH-006 Verification Record

## Scope

Hardened the Intel HiDPI command and menu around the boundaries found after
IH-004:

- A downloaded `hidpi.sh` can run through `bash -c` without requiring or
  loading local Intel helper files. It retains legacy options 1 through 3.
- Native resolution, framebuffer limit, and EDID input are validated before
  Bash arithmetic or EDID field extraction.
- Apply failure removes temporary files and only the empty directories created
  by that invocation. Existing state is retained for manual inspection.
- Original override backups and restored files retain their original metadata
  through `cp -p`; generated candidate and manifest files remain normalized.
- Apply and revert normalize roots, reject user-controlled symbolic-link path
  components, use a per-display `shlock` lock, and protect the standard macOS
  `/tmp` and `/var` aliases by normalizing them to `/private` before traversal.

The regression tests cover the following behaviors:

- Huge integer resolutions and framebuffer limits are rejected without payload
  generation or apply artifacts.
- Odd-length EDIDs and EDIDs without the standard header are rejected by both
  `native-resolution` and inventory.
- A single downloaded `hidpi.sh`, including the `bash -c` execution model,
  keeps legacy menu dispatch and never loads an adjacent helper fixture.
- Existing `0600` and `0640` override files preserve their modes after backup
  and revert.
- Invalid apply requests leave no new vendor or per-display state directories.
- Root, vendor, state, and revert-target symbolic-link paths are rejected.
- A competing display lock is rejected before target mutation.
- A process terminated while holding a display lock removes that lock through
  its exit cleanup, so a later operation is not blocked by a stale lock.
- Lexical and data-volume spellings of the system Overrides path still require
  root. A custom root under the macOS `/tmp` alias can still apply and revert.

## Remaining Boundary

The lock serializes cooperating invocations of this tool for one display. It
does not make hash verification and a later filesystem replacement atomic
against a malicious or non-cooperating external root process. The existing
hash checks and same-directory atomic moves remain in place, but this residual
TOCTOU boundary requires filesystem-level coordination outside this shell tool.

No command in this task wrote to `/Library/Displays` or
`/Library/Application Support`. IH-005 remains the separate, user-authorized
real-display validation task.
