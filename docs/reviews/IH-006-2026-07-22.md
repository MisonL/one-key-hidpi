# IH-006 验证记录

## 范围

围绕 IH-004 之后发现的边界加固 Intel HiDPI 命令和菜单：

- 下载得到的 `hidpi.sh` 可以通过 `bash -c` 运行，无需或加载本地 Intel 辅助文件，并保留旧菜单
  选项 1 至 3；
- 在 Bash 算术或 EDID 字段提取前校验原生分辨率、framebuffer 上限和 EDID 输入；
- apply 失败时删除临时文件和本次调用创建的空目录，保留既有状态供人工检查；
- 原始 override 备份和恢复文件通过 `cp -p` 保留原始元数据，生成的候选和 manifest 文件保持
 规范化；
- apply 和 revert 规范化根路径，拒绝用户控制的符号链接路径组件，使用按显示器划分的
  `shlock` 锁，并在遍历前将标准 macOS `/tmp` 和 `/var` 别名规范化到 `/private`。

## 自动验证

以下命令均以退出码 0 完成：

```sh
bash tests/test_intel_hidpi_inventory.sh
bash tests/test_intel_hidpi_preview.sh
bash tests/test_intel_hidpi_apply_revert.sh
bash tests/test_intel_hidpi_menu.sh
bash -n hidpi.sh intel-hidpi.sh lib/intel_hidpi_storage.sh \
  lib/intel_hidpi_menu.sh tests/test_intel_hidpi_inventory.sh \
  tests/test_intel_hidpi_preview.sh tests/test_intel_hidpi_apply_revert.sh \
  tests/test_intel_hidpi_menu.sh
shellcheck -s bash intel-hidpi.sh lib/intel_hidpi_storage.sh \
  lib/intel_hidpi_menu.sh tests/test_intel_hidpi_inventory.sh \
  tests/test_intel_hidpi_preview.sh tests/test_intel_hidpi_apply_revert.sh \
  tests/test_intel_hidpi_menu.sh
git diff --check
```

回归测试覆盖：

- 拒绝超大整数分辨率和 framebuffer 上限，且不生成 payload 或 apply 工件；
- `native-resolution` 和盘点命令拒绝奇数长度 EDID 以及缺少标准头的 EDID；
- 单个下载的 `hidpi.sh`（包括 `bash -c` 执行模型）保持旧菜单分派，且绝不加载相邻的辅助
  fixture；
- 既有 `0600` 和 `0640` override 文件在备份和回退后保留权限；
- 非法 apply 请求不留下新的 vendor 或单显示器状态目录；
- 拒绝 root、vendor、state 和回退目标的符号链接路径；
- 竞争中的显示器锁会在目标修改前被拒绝；
- 持有显示器锁的进程被终止后，退出清理会移除该锁，后续操作不会被陈旧锁阻塞；
- 系统 Overrides 路径的词法拼写和数据卷拼写都仍要求 root；macOS `/tmp` 别名下的自定义根
  仍可执行 apply 和 revert。

## 剩余边界

该锁只为同一显示器的本工具协作调用提供串行化。它不能让哈希核验与后续文件系统替换相对于
恶意或不协作的外部根进程具备原子性。现有哈希检查和同目录原子移动仍然保留，但这个剩余的
TOCTOU 边界需要 shell 工具之外的文件系统级协调。

本任务没有向 `/Library/Displays` 或 `/Library/Application Support` 写入任何内容。IH-005 仍是
独立的、需要用户授权的真实显示器验证任务。
