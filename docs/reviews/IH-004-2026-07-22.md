# IH-004 验证记录

## 范围

在现有 `hidpi.sh` 菜单中增加 Intel 专用的 `Intel safe HiDPI` 选项。该选项读取选定显示器
的 EDID，通过 `intel-hidpi.sh native-resolution` 得到首选面板分辨率，预览有界的生成模式，
并提供应用、回退或取消操作。

显示器选择现在由 `select_display` 完成，它不会初始化旧的 override 路径。旧的 `init` 函数
会延迟到用户选择已有菜单操作时才执行。因此，预览或取消不会创建 `/Library/Displays`、
生成旧的恢复脚本或创建旧的临时目录。

菜单库不会调用 `sudo`。apply 和 revert 要求父进程已经拥有 root 身份，并在调用独立安全工具
前输入精确的 `APPLY` 或 `REVERT` 确认词。

## 自动验证

以下命令均以退出码 0 完成：

```sh
bash tests/test_intel_hidpi_inventory.sh
bash tests/test_intel_hidpi_preview.sh
bash tests/test_intel_hidpi_apply_revert.sh
bash tests/test_intel_hidpi_menu.sh
bash -n hidpi.sh intel-hidpi.sh lib/intel_hidpi_storage.sh lib/intel_hidpi_menu.sh \
  tests/test_intel_hidpi_inventory.sh tests/test_intel_hidpi_preview.sh \
  tests/test_intel_hidpi_apply_revert.sh tests/test_intel_hidpi_menu.sh
shellcheck -s bash intel-hidpi.sh lib/intel_hidpi_storage.sh lib/intel_hidpi_menu.sh \
  tests/test_intel_hidpi_inventory.sh tests/test_intel_hidpi_preview.sh \
  tests/test_intel_hidpi_apply_revert.sh tests/test_intel_hidpi_menu.sh
git diff --check
```

菜单测试验证：

- 预览后取消会计算 EDID 原生分辨率，并且不调用安全工具的写入操作；
- 安全菜单函数不含 `sudo` 调用；
- 非 root 的 apply 选择会在确认或写入前显式失败；
- 新的 Intel 选项分派时不会调用旧的 `init`；
- 既有 Intel 菜单映射保持为 `1 -> init + enable`、`2 -> init + enable with EDID patch`、
  `3 -> init + disable`。

对历史 `hidpi.sh` 执行完整 ShellCheck 时仍会报告本任务范围外的既有诊断。其 Bash 语法检查
通过；新的菜单库和所有新增或独立的 Intel 脚本均通过 ShellCheck。

## 实机只读检查

主机为 `x86_64`，uid 为 `501`。连接的显示器盘点识别出 `LS27D80xU`，标识为 `4c2d:7668`，
原生分辨率为 `3840x2160`，且没有已有 override。

交互输入依次选定该显示器、选择菜单选项 `4`，再选择 `3` 取消。菜单显示五个生成模式并以退出码
0 结束。`/Library/Displays` 下所有文件的前后 SHA-256 快照相同。没有执行 apply、revert、
重启、睡眠或重新连接显示器。
