# IH-004 Verification Record

## Scope

Added an Intel-only `Intel safe HiDPI` option to the existing `hidpi.sh`
menu. The option reads the selected display EDID, derives its preferred panel
resolution through `intel-hidpi.sh native-resolution`, previews the bounded
generated modes, and offers apply, revert, or cancel.

Display selection now happens in `select_display`, which does not initialize
legacy override paths. The legacy `init` function is deferred until a user
chooses an existing menu operation. This prevents a preview or cancel action
from creating `/Library/Displays`, generating the legacy restore script, or
creating the legacy temporary directory.

The menu library does not invoke `sudo`. Apply and revert require an already
root-owned parent process and an exact `APPLY` or `REVERT` confirmation before
calling the separate safe tool.

- Preview followed by cancel computes the EDID native resolution and does not

- The safe menu function contains no `sudo` invocation.
- A non-root apply selection fails explicitly before confirmation or writing.
- The new Intel option dispatches without calling legacy `init`.
- Existing Intel menu mappings remain `1 -> init + enable`,
  `2 -> init + enable with EDID patch`, and `3 -> init + disable`.
