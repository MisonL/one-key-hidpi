# IH-017 验证记录

## 范围

本任务修复运行时 HiDPI 接受情况的证据缺口，增加只读 `verify-modes` 命令。命令按 vendor 和
product ID 精确解析一台在线显示器，然后将每个生成的逻辑模式与所需的 2x framebuffer 比较。

它不会调用 apply 或 revert，不会写入 override、改变分辨率、重载显示服务、睡眠或唤醒主机、
重新连接显示器或重启系统。

## 问题分析

历史上的重启后 CoreGraphics 枚举使用 `CGMainDisplayID()`。该 API 返回 macOS 当前标记为主显示器
的设备，而不是实验中选定的 Lenovo `30ae:62a5`。多显示器布局中的主显示器可变，因此输出中
看似匹配的模式可能属于另一台显示器，记录无法证明 Lenovo 模式是完整暴露还是部分暴露。

之后 Lenovo override 已恢复为精确原始内容。当前只读基线无法证明临时候选 override 激活后的行为，
因为它已经不再安装。底层驱动是否接受四个未观察到的生成模式仍明确未知，不会被静默归因于生成器
或 payload 格式。

## 已实现行为

- `verify-modes` 接受 vendor ID、product ID 和原生分辨率；
- 未使用 `--modes-file` 时，Swift 辅助程序通过 CoreGraphics 读取精确匹配的在线显示器。它会在
  获取第二份排序 ID 快照前再次检查在线显示器数量，在模式枚举后再次比较完整快照，并在捕获期间
  保留选定显示器序列号。显示器列表变化、无匹配或多匹配都会被拒绝，不会任意选择；
- 命令校验捕获语法，并比较 `logical` 与 `pixels` 尺寸。相同逻辑分辨率但 framebuffer 非 HiDPI
  不算已观察；
- 输出将来源标记为 `live-coregraphics` 或 `offline-file`。离线结果只校验给定捕获，不是实机观察；
- 退出状态 `0` 表示观察到全部生成候选，退出状态 `2` 表示部分结果并打印每个缺失候选。无效
  捕获和目标不匹配会显式失败；
- 生成候选无法表示的原生尺寸会返回显式候选生成错误，而不是静默以非零退出；
- `--modes-file` 接受离线捕获记录，但必须是大小不超过 1 MiB 的普通非符号链接文本文件，结果
  会标记为离线，不会标记为在线显示器观察；
- 每个命令选项只能使用一次。重复的 vendor、product、原生分辨率或捕获文件选项会显式失败，
  不会静默替换之前的值。

  lib/intel_hidpi_verify_modes.sh tests/test_intel_hidpi_verify_modes.sh

完整串行套件在允许含有锁生命周期覆盖的 `test_intel_hidpi_apply_revert.sh` 不受外部超时地
完成后成功结束。所有 apply/revert fixture 写入仍位于 `mktemp` 根目录，没有触及真实显示器 override。

fixture 覆盖完整的目标绑定捕获、部分捕获、仅逻辑尺寸的非 HiDPI 匹配、目标不匹配、畸形和重复
目标记录、尾随字段、重复 vendor/product/原生分辨率/捕获文件选项、不可表示的候选集、二进制
或符号链接捕获路径、规范化十六进制 ID 和无关的 5K 模式。它还会拒绝超大和空的 `--modes-file`，
不回退到实时捕获。

## 只读本机观察

命令针对使用原始恢复 override 的在线 Lenovo `30ae:62a5` 运行。这是只读查询，返回状态 `2`：

```text
capture-source=live-coregraphics
target=30ae:62a5
compact: 960x540 framebuffer=1920x1080 status=observed
balanced: 1152x648 framebuffer=2304x1296 status=missing
spacious: 1280x720 framebuffer=2560x1440 status=missing
dense: 1440x810 framebuffer=2880x1620 status=missing
native: 1920x1080 framebuffer=3840x2160 status=missing
verification=partial observed=1 missing=4
```

这是恢复后的原始 override 的基线观察，不是对已回退候选 override 的结论。查询没有改变显示配置。

## 剩余边界

该命令解决了目标选择和报告缺口，但不能在没有单独授权的真实 apply 和生命周期激活测试时证明
macOS 会接受新写入的 EDID payload。该测试仍在永久禁止重载和真实写入的边界之外。

CoreGraphics 不提供覆盖完整显示配置的锁。辅助程序在捕获前验证两份稳定的在线列表快照，在模式
枚举后再次比较完整的显示器 ID 快照，并检查选定显示器序列号。观察到列表或目标身份变化时会失败。
无法被这些快照观察到的瞬时硬件变化属于外部 OS 边界，不能作为 payload 已接受的证据。
