# IH-017 Verification Record

## Scope

This task fixes an evidence gap in runtime HiDPI acceptance. It adds a
read-only `verify-modes` command. The command resolves exactly one online
display by vendor and product ID, then compares each generated logical mode
with its required 2x framebuffer.

It does not call apply or revert, write an override, change a resolution,
reload a display service, sleep or wake the host, reconnect a display, or
reboot the system.

## Problem Analysis

The historical post-reboot CoreGraphics enumeration used `CGMainDisplayID()`.
That API reports whichever display macOS currently marks as main, not the
Lenovo `30ae:62a5` selected for the experiment. The main display is mutable in
a multi-display layout, so a matching-looking mode in that output could belong
to the other display. The record could therefore not prove either complete or
partial Lenovo exposure.

The Lenovo override was later restored to its exact original content. A
current read-only baseline cannot prove how the temporary candidate override
would have behaved after activation, because it is no longer installed. The
underlying driver acceptance of the four unobserved generated modes is thus
explicitly unknown, not silently attributed to the generator or to a payload
format.

## Implemented Behavior

- `verify-modes` accepts vendor ID, product ID, and native resolution.
- Without `--modes-file`, a small Swift helper reads the exact matching online
  display through CoreGraphics. It rechecks the online-display count before
  obtaining a second sorted ID snapshot, compares the full snapshot again after
  mode enumeration, and preserves the selected display serial number across
  the capture. It rejects a changed list, no match, or multiple matches rather
  than choosing an arbitrary display.
- The command validates the capture grammar and compares both `logical` and
  `pixels` dimensions. A same logical resolution with a non-HiDPI framebuffer
  does not count as observed.
- The output labels the source as `live-coregraphics` or `offline-file`. An
  offline result validates only the supplied capture and is not a live
  hardware observation.
- Exit status `0` means all generated candidates were observed. Exit status
  `2` means the result is partial and prints every missing candidate. Invalid
  captures and target mismatches fail explicitly.
- A native size whose generated candidates cannot be represented fails with an
  explicit candidate-generation error instead of a silent nonzero exit.
- `--modes-file` accepts an offline captured record. It must be a regular,
  non-symbolic-link text file no larger than 1 MiB, and its result is labeled
  as offline rather than a live display observation.
- Every command option is single-use. Duplicate vendor, product, native
  resolution, or capture-file options fail explicitly instead of silently
  replacing an earlier value.

## Read-Only Local Observation

The command was run against the online Lenovo `30ae:62a5` using its original
restored override. It was a read-only query and returned status `2`:

```text
capture-source=live-coregraphics
target=30ae:62a5
compact: 960x540 framebuffer=1920x1080 status=observed
balanced: 1152x648 framebuffer=2304x1296 status=missing
spacious: 1280x720 framebuffer=2560x1440 status=missing
dense: 1440x810 framebuffer=2880x1620 status=missing
native: 1920x1080 framebuffer=3840x2160 status=missing
verification=partial observed=1 missing=4
```

This is a baseline observation of the restored original override, not a claim
about the reverted candidate override. The query did not alter display
configuration.

## Remaining Boundary

The command closes the target-selection and reporting gap. It cannot prove
that macOS will accept newly written EDID payloads without a separately
authorized real apply and lifecycle activation test. That test remains outside
the permanent no-reload and no-real-write operating boundary.

CoreGraphics does not provide a lock over the complete display configuration.
The helper validates two stable online-list snapshots before capture, then
compares the full sorted display-ID snapshot again after mode enumeration and
also checks the selected display serial number. It fails when it observes a
changed list or target identity. A transient hardware change that cannot be
observed by those snapshots remains an external OS boundary, not evidence of
payload acceptance.
