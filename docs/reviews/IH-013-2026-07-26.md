# IH-013 验证记录

## 范围

本任务收口 Intel 安全 HiDPI 已存在 target 的 replace 路径在第一次 `RENAME_SWAP` 前的内容竞态。

未写入 `/Library/Displays`、`/Library/Application Support` 或其他真实系统显示器 override 路径。
所有写入验证均在测试创建的临时目录 fixture 中执行；未使用 `sudo`。

## 根因与修复

此前 replace 在 staged 文件创建后，只重新确认 staged 和 target pathname 仍绑定已打开的文件
描述符。`device:inode` 未变化时，竞争方可原地改写文件内容而保持身份不变，第一次 swap 因而
可能基于过期内容快照执行。

- `staged_path_matches` 现在同时要求 pathname 仍绑定 staged 文件描述符，并且 staged 文件的
  SHA-256 仍等于已验证 candidate hash；
- `target_path_matches` 现在同时要求 pathname 仍绑定 target 文件描述符，并且 target 文件的
  SHA-256 仍等于 replace 前的 target hash；
- target 原地改写时，已验证的 staged candidate 会被精确清理，replace 在首次 swap 前以状态 1
  失败，target 保留竞争内容；
- staged 原地改写时，工具不能再证明 staged 工件属于自己，因此保留 target 和 staged 工件，以
  状态 2 失败并要求人工检查；
- replace 分支仍只有一个 `RENAME_SWAP` 调用，失败路径不会执行补偿交换。

## 回归覆盖

- target 内容竞态：测试暂停自行启动的 Ruby replace 子进程，在第一次 swap 前原地写入 target。
  断言 inode 不变、首次 swap 被拒绝、target 保留竞争内容、candidate hash 未变，且已验证 staged
  文件被清理；
- staged 内容竞态：测试在临时复制的 FFI helper 中于 staged 初次 SHA-256 完成后暂停 Ruby 子进程。
  确认子进程已停止、staged 内容仍等于 candidate hash 后，原地改写 staged 文件并恢复进程。
  断言 target 保留原内容、candidate 保持原始 hash、改写后的 staged 工件保留且首次 swap 未发生；
- swap 后 staged 路径目录竞态的断言改用操作前固定的 candidate hash，避免重算时受竞争方路径内容
  影响；
- 结构断言确认 replace 分支只有一次 `RENAME_SWAP`，没有恢复性第二次 swap helper。

## 保留边界

- `renameatx_np(RENAME_SWAP)` 没有携带预期 inode 或 hash 的条件提交接口。非协作高权限进程仍可
  在最后一次 hash 校验与系统调用之间改写或替换路径项；当前实现缩小该窗口，并在发现不一致时
  fail-closed，不执行第二次 swap，不能将此表述为对非协作 root 的绝对原子保护；
- 真实 Intel 黑苹果显示器的启用、重启、睡眠、拔插和精确回退仍属于 IH-005，未经用户明确 root
  授权不得执行；
- `tests/test_intel_hidpi_storage_races.sh` 现超过 1000 行，但它表达一个连续的文件身份与竞态
  状态机。拆分会复制跨步骤 fixture 和清理协议，降低竞态因果链的可审计性，因此记录该单一测试
  文件的复杂度豁免。
