# IH-007 Verification Record

## Scope

Hardened the read-only Intel display inventory boundary in `intel-hidpi.sh`.

- EDID input must contain complete 128-byte blocks, use the standard header,
  and have a valid base-block checksum.
- Display names are read only from the four formal base-block descriptors and
  are limited to printable ASCII before output.
- Inventory normalizes vendor and product IDs with the same helper as apply and
  revert, so paths do not retain leading zeroes.
- A malformed existing override is reported as invalid without attempting mode
  extraction.

The fixture EDIDs were corrected to valid 128-byte base blocks while retaining
the prior display identities, names, and preferred resolutions.

The inventory regression covers:

- valid multi-display inventory and native resolution parsing;
- incomplete, header-invalid, odd-length, and checksum-invalid EDIDs;
- a monitor-name descriptor containing an escape byte;
- leading-zero vendor and product IDs resolving to the same override names as
  apply and revert; and
- a malformed existing plist reported as `invalid` with mode data marked
  unavailable.

No command in this task wrote to `/Library/Displays` or
`/Library/Application Support`.
