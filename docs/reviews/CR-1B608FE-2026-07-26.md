# 提交 1b608fe 安全差异复核

提交 `1b608feff2f413554dd5de7511b80695c35e3ff5` 相对父提交
`44f0301a9ad9f446f9179b84a70503998d4d4043` 不应作为安全闭环版本通过。

或其他真实显示器 override 路径。所有行为验证均在 `/private/tmp` 或测试自身的

## 发现

### P1: 自动补偿 swap 可把未验证对象放回 target

`1b608fe:lib/intel_hidpi_darwin_fs.sh:465-477` 的
`restore_failed_swap` 在第二次 `RENAME_SWAP` 前只确认 target 仍指向 candidate
的文件描述符，没有确认 staged 路径仍是原 target；交换后也只确认 staged
重新指向 candidate。调用点位于 `1b608fe:lib/intel_hidpi_darwin_fs.sh:690-715`。

目标提交自己的竞态 fixture 已暴露该语义：
`1b608fe:tests/test_intel_hidpi_storage_races.sh:700-739` 在 staged 出现后把 target
替换为竞争目录，随后断言第二次 swap 把该竞争目录留在 target，并接受
`target was restored` 的成功恢复文案。这不是原 target 恢复，而是把未验证对象
重新发布到目标名称。

影响是失败路径主动改变 target，并可能误报已经恢复。`8cdb982` 删除了补偿 swap；
当前回归还用结构断言禁止恢复 helper 重新出现。

### P1: 首次 swap 前没有重新绑定 staged 路径

`1b608fe:lib/intel_hidpi_darwin_fs.sh:648-658` 创建并校验 staged 文件描述符后，
直接按 staged 名称执行 `RENAME_SWAP`，没有再次确认该名称仍指向 staged FD。
拥有目标父目录写权限的竞争进程可在窗口内把 staged 名称替换为文件或目录，
使首次 swap 把竞争对象放入 target，并把原 target 移到隐藏 staged 名称。

目标提交的测试只替换 target，没有替换 staged 名称。`8cdb982` 增加首次 swap 前
的双边 pathname/FD 绑定检查，并新增 staged 名称替换 fixture。

### P2: 恢复脚本直接覆盖最终路径并跟随链接

`1b608fe:hidpi.sh:552-560` 只检查 HOME 可写；`1b608fe:hidpi.sh:563`、`:651`
直接以 `cat > "$restore_script"` 截断 `.hidpi-disable`，`:698-705` 继续追加，
`:756` 对最终路径执行 `chmod`。没有拒绝既有普通文件、符号链接或硬链接，也没有
私有 staging 和原子无覆盖发布。

隔离复现中，预置符号链接和硬链接后两次 `generate_restore_cmd` 均返回 0，两个
外部目标的首行都从 sentinel 变成 `#!/bin/bash`；硬链接目标链接数保持 2，权限
被改为 0755。后续 `8cdb982` 改为 HOME 内私有 staging、0700 权限和
`RENAME_EXCL | RENAME_NOFOLLOW_ANY` 发布。

### P2: `fclonefileat` 创建后按名称重开，无法绑定创建对象

`1b608fe:lib/intel_hidpi_darwin_fs.sh:273-301` 用 `fclonefileat` 创建目标后，
再通过 pathname 调用 `open_regular_file`。函数没有持有新建对象的原始 FD；若名称
在创建和重开之间被同内容不同 inode 文件替换，后续校验只能绑定竞争对象，无法
证明它就是本次创建的对象。该 helper 同时用于新 target 安装和 replace staging。

`8cdb982` 改为先用 `openat(O_CREAT | O_EXCL | O_NOFOLLOW)` 获得目标 FD，再在
已打开的 source/target FD 之间执行 `fcopyfile`。

### P2: 首次 swap 前没有重新校验内容

`1b608fe:lib/intel_hidpi_darwin_fs.sh:643-652` 在创建 staging 前校验 target
内容，在 staging 创建后只校验一次 staged 内容；到第一次 swap 前没有再次计算
两边 SHA-256。同 inode 原地改写不会改变 `device:inode`，因此可基于过期快照执行
第一次 swap。

`6949f51` 在首次 swap 前同时重验 target 和 staged 的路径绑定及 SHA-256，并补充
两种同 inode 内容竞态 fixture。

### P2: 自定义 state 根没有可信来源约束

`1b608fe:lib/intel_hidpi_storage.sh:304-306` 只规范化两个根并检查系统路径需要
root；`1b608fe:lib/intel_hidpi_manifest.sh:173-236` 验证 manifest 当前内容、字段、
hash 和 inode，但没有证明 state 目录由本工具在可信根创建。target 缺失且
`target-existed=true` 时，`1b608fe:lib/intel_hidpi_storage.sh:392-421` 会把该根下
的 `original.plist` 安装为 target。

隔离复现使用手工构造的合法 v4 manifest 和 `original.plist`，在 target 缺失时
执行 revert，命令退出码为 0 并创建了目标。自定义/自定义组合本身是测试能力；
风险出现在特权调用把系统 Overrides 根与攻击者可写 state 根混用时。复核时的
`HEAD` 仍允许该组合，已登记 `IH-014`，要求系统根只能与系统根配对。

### P3: 目录创建后的归属记录存在 reopen 窗口

`1b608fe:lib/intel_hidpi_darwin_fs.sh:98-113` 在 `mkdirat` 成功后按名称重新打开
目录，再把重开对象的 identity 记录为“本次创建”；`1b608fe:lib/intel_hidpi_storage_support.sh:46-63`
随后可能按该 identity 清理空目录。名称若在 mkdir 和 reopen 之间被替换，记录的
是竞争目录，而不是本工具创建的目录。

`8cdb982` 停止宣称这种目录归属并取消自动清理；无法由创建 syscall 返回 FD 的
目录在失败时保留，避免删除竞争对象。

### 继承边界: Recovery 脚本依赖当前目录并保留全量递归删除

`1b608fe:hidpi.sh:714-715` 从进程当前目录计算 `../../Library/.../Overrides`，
而不是从脚本自身位置解析系统卷；`:743-744` 的 option 2 对该相对路径执行
`rm -rf`，且未检查返回值，之后仍打印成功。该行为在父提交中已经存在，不属于
本提交新增回归，但目标提交修改了同一恢复脚本且未消除它，复核时的 `HEAD` 仍然
保留。已登记 `IH-015`。

## 未作为缺陷的问题

- legacy choice 3 在 `init` 失败后停止，是文档和测试明确固化的 fail-closed
  策略；虽然 HOME 不可写时会降低可用性，但本审计不把显式失败改判为安全缺陷。
- `RENAME_NOFOLLOW_ANY` 不提供 inode 条件交换；最后一次校验与 syscall 之间仍有
  无法完全消除的窗口。当前策略应继续表述为尽量缩小窗口并保留现场，不能声称对
  非协作 root 具有绝对原子性。
- `intel-hidpi.sh` 在本差异中只删除旧的本地 `MANIFEST_VERSION=2` 常量，实际
  manifest 版本由新模块提供，未发现独立行为回归。
