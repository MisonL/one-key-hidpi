# IH-011 验证记录

## 范围

本任务完成旧菜单单显示器回退和 Intel 安全 HiDPI 状态提交/回退的复核加固。
未写入 `/Library/Displays`、`/Library/Application Support` 或其他系统显示器
override 路径；所有写入验收均在临时目录 fixture 中执行。

## 已实现的边界

- 旧菜单和生成的 `.hidpi-disable` 在 vendor 路径为符号链接或普通文件时
  显式失败，不删除该路径指向的外部内容。
- 两条旧回退路径只删除当前产品的 plist、`.icns` 和 `.tiff`，并保留 legacy
  vendor 目录，避免 pathname-only `rmdir` 在名称被替换后误删竞争方空目录；
  同厂商 sibling 保留。旧菜单的 vendor 目录和
  `Icons.plist` 都通过 `openat`、`O_NOFOLLOW` 和文件描述符操作，拒绝符号链接、
  普通文件及硬链接的 `Icons.plist`。
- Intel apply 对 `original.plist`、`manifest.plist` 和新建 target 通过
  `openat` 加 `fclonefileat`（不支持时使用 `O_EXCL` 加 `fcopyfile`）无覆盖
  安装。发生竞争时保留已存在的竞争文件和工具状态，要求人工检查。
- Intel revert 在 target 缺失时，按已验证 manifest 恢复原有 plist，或精确
  清理工具创建 target 的状态。
- 现有 target 的 apply/revert 替换在提交前再次确认 target 为非符号链接的
  常规文件，并使用同目录 `renameatx_np(RENAME_SWAP | RENAME_NOFOLLOW_ANY)`。
  若该组件在检查后变成目录或目录符号链接，交换失败且候选内容不会被移动到
  该目录。
- 本次创建的目录、锁目录、私有临时目录和回退后的 state 目录都记录
  `device:inode`。清理时先以父目录 FD 将目录转入唯一隔离名，再验证身份并
  只删除空目录；身份变化、非空或无法恢复时保留现场。

`tests/test_intel_hidpi_storage_races.sh` 复现了最后一项：旧的 `mv -f`
会在 post-validation 目录符号链接竞争中把候选文件移入外部目录；即使改成
`mv -h`，真实目录竞争仍会使候选文件被移入该目录。修复后的
`renameatx_np` 对目录和目录符号链接都失败；apply 和 revert 均保留 state，
外部目录保持为空。该测试还使用真实 Ruby 子进程持有目标 FD，在删除操作后
暂停该进程、替换 pathname 为竞争目录、再恢复进程，确认删除拒绝、竞争目录
不受影响且不留下隐藏隔离条目。

本轮还修正了两个 Darwin 临时路径 fixture 的口径，而未放宽生产路径校验：

- storage root 的预期先做词法清理，再将 `/tmp` 和 `/var` 映射到 Darwin 的
  `/private` 别名；随后仍把该根替换为符号链接，确认 descriptor-based 创建拒绝
  该替换。
- 锁目录别名 fixture 固定在实际 `/private/tmp` 根下，并经 `/tmp` 访问同一
  目录。其失败清理只接受 `/private/tmp/one-key-hidpi-alias-lock-*` 前缀，防止
  `TMPDIR=/var/folders/...` 时把两个不同目录误当成别名。

## 自动验证

以下命令在当前工作树以退出码 0 完成。最终长时 fixture 均以串行方式
执行：`storage-races` 和 `apply-revert` 的最终输出分别为
`PASS: Intel HiDPI storage races` 与 `PASS: Intel HiDPI apply and revert`。
并行执行只会令 Darwin FFI fixture 显著变慢，因此不将中间会话状态作为通过
证据。所有写入仍仅发生在测试创建的临时目录。

```sh
bash tests/test_intel_hidpi_inventory.sh
bash tests/test_intel_hidpi_preview.sh
bash tests/test_intel_hidpi_apply_revert.sh
bash tests/test_intel_hidpi_menu.sh
bash tests/test_intel_hidpi_legacy_cleanup.sh
bash tests/test_intel_hidpi_storage_races.sh
bash -n hidpi.sh intel-hidpi.sh lib/intel_hidpi_darwin_fs.sh \
  lib/intel_hidpi_manifest.sh lib/intel_hidpi_storage.sh \
  lib/intel_hidpi_storage_support.sh \
  tests/test_intel_hidpi_inventory.sh tests/test_intel_hidpi_preview.sh \
  tests/test_intel_hidpi_apply_revert.sh tests/test_intel_hidpi_menu.sh \
  tests/test_intel_hidpi_legacy_cleanup.sh \
  tests/test_intel_hidpi_storage_races.sh
shellcheck -s bash intel-hidpi.sh lib/intel_hidpi_darwin_fs.sh \
  lib/intel_hidpi_manifest.sh lib/intel_hidpi_storage.sh \
  lib/intel_hidpi_storage_support.sh \
  tests/test_intel_hidpi_inventory.sh tests/test_intel_hidpi_preview.sh \
  tests/test_intel_hidpi_apply_revert.sh tests/test_intel_hidpi_menu.sh \
  tests/test_intel_hidpi_legacy_cleanup.sh \
  tests/test_intel_hidpi_storage_races.sh
git diff --check
```

完整 `hidpi.sh` 的 ShellCheck 仍返回非零：当前与 `HEAD` 相同保留 6 个
`SC2068` error；本任务没有新增 ShellCheck 类别，且不扩展到无关的历史菜单
重构。
新增 Darwin 文件操作层、manifest 层、storage support 和所有聚焦测试文件的
ShellCheck 为零。

本轮还为旧恢复脚本补充了两个失败路径：`HOME` 未设置或不可写时显式失败，且
`init` 在生成恢复脚本失败时不会继续创建临时目录或准备 legacy override 路径。
`start` 也会在任一 legacy `init` 失败后停止，避免后续启用、EDID 注入或回退
路径继续运行。

## 复杂度豁免

- `lib/intel_hidpi_darwin_fs.sh` 超过 800 行，但内容是单一的 Darwin
  descriptor-based 文件操作边界；将 Ruby FFI 片段拆散会破坏同一进程内的 FD
  生命周期与错误恢复关系，因此保留为一个内聚文件。
- `tests/test_intel_hidpi_apply_revert.sh` 和
  `tests/test_intel_hidpi_storage_races.sh` 超过 800 行。二者按完整 state
  生命周期和竞态序列组织，拆分会重复 fixture、降低跨步骤断言的可读性，故本
  任务保留并以分区变量和显式 fail-closed 断言维持可审计性。
- `hidpi.sh` 已是上游遗留入口且超过 800 行。本任务只在旧回退边界增加小型
  安全函数，不进行会改变菜单行为的大规模拆分。

## 仍需显式保留的边界

- 非协作 root 进程仍可在 Shell 调用边界之间替换父目录或 state 路径组件。
  当前 Darwin FFI 在一次操作内沿路径用 `openat` 和 `O_NOFOLLOW` 打开目录，
  并对最终条目使用无覆盖安装、`renameatx_np`、身份校验和隔离删除；但跨多次
  FFI 调用仍无法把整条 apply/revert 流程锁成一个不可中断的内核事务。
- 同一类非协作 root 竞争可在 legacy vendor 检查之后替换其父路径。该威胁
  需要修改受 root 保护的 Overrides 树，不能仅靠 Shell 消除。
- legacy 回退不再尝试删除空 vendor 目录。目录删除没有可携带预期 inode 的
  原子接口；保留一个空目录没有功能副作用，但能避免在最后一次 `rmdir` 前删除
  被替换的同名空目录。
- 进程崩溃或断电可能留下 manifest/backup 的部分状态。实现选择保留状态并
  显式失败，避免自动删除可能属于竞争方的文件。
- 睡眠、拔插、重启和真实 Intel 黑苹果显示器行为属于 `IH-005` 的实机验收，
  该任务仍为未开始，未经用户 root 授权不得执行。

IH-011 的可自动验证验收项已完成；上述边界不应被表述为事实上的 100% 安全
保证。
