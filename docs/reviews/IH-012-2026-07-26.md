# IH-012 验证记录

## 范围

本任务收口恢复脚本的无覆盖发布，以及 Intel 安全 HiDPI 文件替换在首次 swap 后验证失败时的
失败语义。未写入 `/Library/Displays`、`/Library/Application Support` 或其他系统显示器 override
路径，所有写入验证均在测试创建的临时目录 fixture 中执行。

## 已实现边界

- `generate_restore_cmd` 先在 `$HOME` 下创建权限为 0700 的私有 staging 目录和临时文件，完整写入
  并设置 0700 权限后才发布 `.hidpi-disable`；生成或权限设置失败时，既有恢复脚本保持不变。
- `legacy_publish_restore_script` 以目录文件描述符打开 staging 父目录和 `$HOME`，拒绝符号链接
  路径、非普通 source、source 硬链接以及任何已有 `.hidpi-disable` 条目。发布使用
  `renameatx_np(RENAME_EXCL | RENAME_NOFOLLOW_ANY)`，不会覆盖普通文件、硬链接或符号链接；发布
  后重新打开并验证目标是同一普通文件。
- 新建 target 和 replace staged 文件均以 `O_CREAT | O_EXCL | O_NOFOLLOW` 创建，再由已打开的
  source 和 target 文件描述符执行 `fcopyfile`，不再按目标 pathname 重开 `fclonefileat`。
- replace 在首次 `RENAME_SWAP` 前验证 target 和 staged 名称仍绑定预期文件。swap 后任一 target
  或 displaced staged 身份、内容或名称校验失败时返回状态 2，保留 target 与 staged 路径供人工
  检查，不执行自动补偿 swap。
- storage race fixture 对新建 target 的同内容替换改为等待 Ruby 实际持有 target 文件描述符后
  暂停进程，再替换 pathname 并恢复。同步点保留 60 秒明确上限。
- staged 路径在首次 swap 前被竞争目录替换、以及首次 swap 后被同内容不同 inode 文件替换的
  fixture 都确认：首次 swap 的 candidate 保留在 target，staged 工件保留，不发生第二次 swap。

文件 ShellCheck 和 `git diff --check` 均通过。完整 `hidpi.sh` 的 ShellCheck 仍包含与 `HEAD`
相同的 6 个 `SC2068` error；本任务没有新增 error，也不扩展到上游遗留菜单的无关重构。

## 保留边界

- 非协作 root 进程仍可在独立 Shell 或 FFI 调用之间替换路径组件。单次文件操作使用目录 FD、
  `O_NOFOLLOW`、无覆盖发布、身份校验和 fail-closed 状态保留，但整个 apply 或 revert 生命周期
  不是不可中断的内核事务。
- 进程崩溃或断电可能留下 staging、manifest 或 backup。实现选择显式失败并保留现场，不自动删除
  身份无法证明的工件。
- 睡眠、拔插、重启和真实 Intel 黑苹果显示器行为仍属于 IH-005，未经用户 root 授权不得执行。
