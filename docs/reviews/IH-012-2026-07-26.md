# IH-012 验证记录

## 范围

本任务收口恢复脚本的无覆盖发布，以及 Intel 安全 HiDPI 文件替换在首次
swap 后验证失败时的失败语义。

未写入 `/Library/Displays`、`/Library/Application Support` 或其他系统显示器
override 路径。所有写入验证均在测试创建的临时目录 fixture 中执行。

## 已实现的边界

- `generate_restore_cmd` 先在 `$HOME` 下创建权限为 0700 的私有 staging
  目录和临时文件，完整写入并设置 0700 权限后才发布 `.hidpi-disable`。
  生成或权限设置失败时，既有恢复脚本保持不变。
- `legacy_publish_restore_script` 以目录文件描述符打开 staging 父目录和
  `$HOME`，拒绝符号链接路径、非普通 source、source 硬链接以及任何已有
  `.hidpi-disable` 条目。发布使用
  `renameatx_np(RENAME_EXCL | RENAME_NOFOLLOW_ANY)`，因此不会覆盖普通文件、
  硬链接或符号链接；发布后重新打开并验证目标为同一普通文件。
- 新建 target 和 replace staged 文件都以 `O_CREAT | O_EXCL | O_NOFOLLOW`
  创建，再由已打开的 source 和 target 文件描述符执行 `fcopyfile`。不再使用
  按目标 pathname 重新打开的 `fclonefileat` 路径。
- replace 在首次 `RENAME_SWAP` 前验证 target 和 staged 名称仍绑定预期文件。
  swap 后任一 target 或 displaced staged 身份、内容或名称校验失败时返回状态
  2，保留 target 与 staged 路径供人工检查；不存在自动补偿 swap。
- storage race fixture 对新建 target 的同内容替换改为等待 Ruby 实际持有
  target 文件描述符后暂停该进程，再替换 pathname 并恢复。此前 fixture 只在
  固定 10 秒内轮询 target 名称；大文件 descriptor copy 使目标可能尚未创建，
  因而产生偶发失败。新同步点保留 60 秒明确上限，但攻击只在已观察到目标 FD
  时执行。
- staged 路径在首次 swap 前被竞争目录替换、以及首次 swap 后被同内容不同
  inode 文件替换的 fixture 都确认：首次 swap 的 candidate 保留在 target，
  staged 工件保留，且不会发生第二次 swap。

本任务新增代码未增加 ShellCheck error，未扩展到上游遗留菜单的无关重构。

## 保留边界

- 非协作 root 进程仍可在独立 Shell 或 FFI 调用之间替换路径组件。单次文件
  操作使用目录 FD、`O_NOFOLLOW`、无覆盖发布、身份校验和 fail-closed 状态保留，
  但整个 apply 或 revert 生命周期不是不可中断的内核事务。
- 进程崩溃或断电可能留下 staging、manifest 或 backup。实现选择显式失败并
  保留现场，不自动删除身份无法证明的工件。
- 睡眠、拔插、重启和真实 Intel 黑苹果显示器行为仍属于 IH-005；未经用户 root
  授权不得执行。
