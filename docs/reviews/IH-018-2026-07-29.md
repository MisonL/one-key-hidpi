# IH-018 Verification Record

## Scope

This task adds an explicit `smooth` Intel HiDPI mode set and an optional
near-native compatibility mode. It preserves the existing five-entry `preset`
set as the default for `preview`, `apply`, and `verify-modes`.

All automated writes used isolated `mktemp` fixture roots. No command in this
task wrote a real display override, changed a live display resolution, reloaded
a display service, rebooted the host, slept or woke the host, or reconnected a
display.

## Implemented Behavior

- `preview`, `apply`, and `verify-modes` accept `--mode-set preset|smooth`.
  `preset` remains the default.
- `smooth` derives its integer step from the native resolution greatest common
  divisor. It produces exact-aspect-ratio 2x HiDPI candidates from the first
  representable size no smaller than two-thirds of native through native size.
  It rejects a panel with fewer than two such candidates and caps the output at
  41 entries.
- On a 1920x1080 panel, `smooth` produces 41 modes from 1280x720 through
  1920x1080 in 16x9 steps. `--include-near-native` explicitly appends
  1920x1079 with a 3840x2158 framebuffer.
- `--include-near-native` is valid only with `--mode-set smooth`. Repeated
  `--mode-set` and `--include-near-native` options fail explicitly for all
  three affected commands.
- `apply` generates and validates its payload set after root and storage-root
  trust validation but before creating a display lock, fixture directory, or
  temporary file. Invalid candidate generation therefore leaves no target or
  state directory behind.
- The generated payload set is passed once into the merge operation. The
  manifest records `mode-set` and `include-near-native` as audit metadata;
  rollback authorization remains based on the existing v5 hashes and
  persistent identities.
- The local Intel safe menu selects preset or smooth, optionally selects the
  near-native entry, previews the exact selection, and forwards the same
  options to `apply`.

## Review

- Static call-site review confirms that all mode-set consumers share the same
  generator: preview output, apply payload construction, and runtime-mode
  verification candidates.
- The existing preset path still uses its original five name and scale entries;
  smooth is opt-in and does not alter default output.
- The new mode generator has bounded integer arithmetic. Native dimensions are
  still limited by the existing 8192 framebuffer maximum, and each emitted
  framebuffer is checked before payload encoding.
- The Intel safe menu does not invoke `sudo`; it keeps the existing explicit
  root check and typed `APPLY` confirmation.
- A command scan found no new invocation of reboot, sleep, wake, display
  service reload, `pmset`, `killall`, `launchctl`, or `defaults write`.

## Remaining Boundary

This is an EDID override candidate generator, not an implementation of
BetterDisplay's private GUI or live display-reconfiguration capability. The
fixture and offline capture results prove deterministic generation, merge,
rollback, and report behavior only. They do not prove that a particular Intel
Hackintosh driver or panel will expose every candidate after a separately
authorized real apply and display lifecycle activation test.

The permanent operating boundary remains: do not apply or revert a real
display override, and do not reboot, sleep, wake, hot-plug, reload, or
reinitialize the display subsystem.
