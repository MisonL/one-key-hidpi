# IH-018 验证记录

## 范围

本任务增加显式的 `smooth` Intel HiDPI 模式集和可选的近原生兼容模式，并保留原有五项
`preset` 集合作为 `preview`、`apply` 和 `verify-modes` 的默认值。

所有自动写入均使用隔离的 `mktemp` fixture 根目录。本任务没有写入真实显示器 override、改变
实时显示分辨率、重载显示服务、重启主机、睡眠或唤醒主机，或重新连接显示器。

## 已实现行为

- `preview`、`apply` 和 `verify-modes` 接受 `--mode-set preset|smooth`，默认仍为 `preset`；
- `smooth` 从原生分辨率最大公约数推导整数步长，从不小于原生尺寸三分之二的第一个可表示尺寸
  生成到原生尺寸，保持精确宽高比，少于两个候选时拒绝面板，最多输出 41 项；
- 对 1920x1080 面板，`smooth` 按 16x9 步长生成从 1280x720 到 1920x1080 的 41 个模式；
  `--include-near-native` 显式追加 1920x1079 和 3840x2158 framebuffer；
- `--include-near-native` 仅在 `--mode-set smooth` 下有效。三个受影响命令中的重复
  `--mode-set` 和 `--include-near-native` 选项都会显式失败；
- `apply` 在 root 和 storage-root 信任验证之后、创建显示器锁、fixture 目录或临时文件之前生成并
  校验 payload 集合，因此候选生成无效时不会留下目标或状态目录；
- 生成的 payload 集合只传入一次合并操作。manifest 将 `mode-set` 和 `include-near-native`
  记录为审计元数据；回退授权仍由现有 v5 哈希和持久身份控制；
- 本地 Intel 安全菜单选择 preset 或 smooth，可选近原生条目，预览精确选择，并将相同选项传给
  `apply`。

## 复核

- 静态调用点复核确认所有模式集消费者共享同一个生成器：预览输出、apply payload 构造和运行时
  模式核验候选；
- 既有 preset 路径仍使用原来的五个名称和缩放条目，smooth 需要显式启用，不改变默认输出；
- 新模式生成器使用有界整数算术。原生尺寸仍受现有 8192 framebuffer 上限限制，每个输出
  framebuffer 在 payload 编码前都会检查；
- Intel 安全菜单不调用 `sudo`，保留现有显式 root 检查和输入 `APPLY` 确认词；
- 命令扫描没有发现新增的重启、睡眠、唤醒、显示服务重载、`pmset`、`killall`、`launchctl` 或
  `defaults write` 调用。

## 剩余边界

这是 EDID override 候选生成器，不是 BetterDisplay 私有 GUI 或实时显示重配置能力的实现。
fixture 和离线捕获结果只证明生成、合并、回退和报告行为具有确定性，不能证明特定 Intel 黑苹果
驱动或面板在另行授权的真实 apply 和显示生命周期激活后会暴露每个候选模式。

永久操作边界仍为：不得对真实显示器执行 apply 或 revert，不得重启、睡眠、唤醒、热插拔、重载
或重初始化显示子系统。
