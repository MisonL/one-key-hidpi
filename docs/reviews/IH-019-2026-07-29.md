# IH-019 验证记录

## 范围

IH-019 退役旧版直接写入入口。`hidpi.sh` 现在只作为本地 Intel 安全交互入口，负责盘点有效
EDID 记录，在必要时要求明确选择显示器，并委托现有 Intel 安全菜单。

退役入口不再包含旧版生成器、远程脚本下载、自动提权、`defaults write` 或宽泛清理实现。
`hidpi.command` 现在拒绝符号链接入口，并使用绝对命令路径解析本地目录。

## 已实现行为

- 入口在加载 Intel 菜单前要求完整且为普通文件的本地 checkout。不完整、缺失或含符号链接的
  辅助文件会显式失败；
- EDID、vendor ID、product ID 和原生分辨率都从一条已验证记录构造。重复 EDID 会忽略；不同
  EDID 如果指向一个 override 路径会被拒绝，而不是任意选择；
- 数字选择在转换数组前先比较字符串长度，因此超大选择不会导致 Bash 算术溢出；
- 入口对 `dirname`、`pwd`、`ioreg` 和直接 Intel 工具使用绝对路径。直接工具及其辅助文件图仍
  保留本地普通文件检查；
- 新入口 fixture 覆盖完整和不完整本地 checkout、辅助文件和入口符号链接、污染的 `PATH`、
  无效和重复 EDID 记录、歧义目标、超大选择输入，以及预览和取消流程；
- 旧版实现退役时删除了 `tests/test_intel_hidpi_legacy_cleanup.sh`。没有活动测试运行器或工作流
  引用它；较早的审查记录保留其历史引用不变。

## 复核

- `hidpi.sh` 只有一条生产路径：验证记录选择后调用 `intel_safe_hidpi`，不保留旧菜单选项或回退；
- 菜单仍要求已有 root 身份，并在调用直接工具的写入命令前输入明确的 `APPLY` 或 `REVERT` 文本，
  菜单自身不调用 `sudo`；
- 直接工具的默认系统路径仍受显式 root 检查和 state-root 信任边界保护。fixture 套件为每个写入
  操作传入自定义 `--overrides-root` 和 `--state-root` 路径；
- README 现在只记录有界的 Intel 安全工作流，并区分 fixture/离线证据与实时显示行为。

## 永久边界

本任务没有应用或回退真实显示器 override。没有命令使用 `sudo`、重载显示服务、重启主机、睡眠
或唤醒主机、热插拔显示器，也没有改变实时显示分辨率。

自动化证据只证明本地入口、校验、候选生成、存储、回退和失败行为在 fixture 中具有确定性，不能
证明特定 Intel 黑苹果驱动、显示器或 macOS 版本在真实 apply 后会暴露所有生成模式。真实设备
apply 或 revert 仍在本任务永久操作边界之外。
