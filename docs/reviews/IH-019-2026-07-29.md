# IH-019 Verification Record

## Scope

IH-019 retires the legacy direct-write entrypoint. `hidpi.sh` is now a local
Intel-safe interaction entrypoint only. It inventories valid EDID records,
requires an explicit display selection where necessary, and delegates to the
existing Intel-safe menu.

The retired entrypoint no longer contains the legacy generator, remote script
download, automatic privilege escalation, `defaults write`, or broad cleanup
implementation. `hidpi.command` now rejects a symlink entrypoint and resolves
its local directory with absolute command paths.

## Implemented Behavior

- The entrypoint requires a complete, regular local checkout before sourcing
  the Intel menu. Missing, partial, or symlinked helpers fail explicitly.
- EDID, vendor ID, product ID, and native resolution are built from one
  validated record. Duplicate EDIDs are ignored. Different EDIDs targeting one
  override path are rejected rather than arbitrarily selected.
- Numeric selection uses a string-length comparison before array conversion,
  so an oversized selection cannot overflow Bash arithmetic.
- The entrypoint uses absolute paths for `dirname`, `pwd`, `ioreg`, and the
  direct Intel tool. The direct tool and its helper graph retain the local
  regular-file checks.
- The new entrypoint fixture covers complete and incomplete local checkouts,
  helper and entrypoint symlinks, a poisoned `PATH`, invalid and duplicate
  EDID records, an ambiguous target, oversized selection input, and a preview
  and cancellation flow.
- `tests/test_intel_hidpi_legacy_cleanup.sh` was removed with the retired
  legacy implementation. No active test runner or workflow references it;
  older review records keep their historical references unchanged.

## Review

- `hidpi.sh` has one production path: validated record selection followed by
  `intel_safe_hidpi`. It does not retain a legacy menu option or fallback.
- The menu still requires an existing root identity and explicit `APPLY` or
  `REVERT` text before it can invoke the direct tool's write commands. It does
  not invoke `sudo` itself.
- The direct tool's default system paths remain guarded by its explicit root
  check and trust-bound state-root validation. The fixture suite passes custom
  `--overrides-root` and `--state-root` paths for every write operation.
- README files now document only the bounded Intel-safe workflow and distinguish
  fixture or offline evidence from live display behavior.

## Permanent Boundary

No real display override was applied or reverted for this task. No command
used `sudo`, reloaded a display service, restarted the host, slept or woke the
host, hot-plugged a display, or changed a live display resolution.

The automated evidence proves deterministic local-entrypoint, validation,
candidate generation, storage, rollback, and failure behavior in fixtures. It
does not prove that a particular Intel Hackintosh driver, monitor, or macOS
release will expose every generated mode after a real apply. A real-device
apply or revert remains outside this task's permanent operating boundary.
