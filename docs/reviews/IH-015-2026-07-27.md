# IH-015 验证记录

## 范围

本任务收口旧版恢复辅助脚本的当前目录依赖和宽泛删除边界，只修改生成的 `.hidpi-disable`
辅助脚本以及旧菜单的禁用选项，不修改 Intel 安全 apply/revert 实现。

本任务没有使用 `sudo`，没有写入 `/Library/Displays` 或 `/Library/Application Support`，没有
改变真实显示器配置，也没有创建真实系统 override。所有写入均限制在 `mktemp` fixture 目录。

## 已实现边界

- `legacy_recovery_volume_root_from_script` 从执行中辅助脚本的 `BASH_SOURCE` 推导卷根，而不是
  从进程当前目录推导。它只接受位于 `<volume>/Users/<user>/` 下的普通 `.hidpi-disable` 文件，
  拒绝符号链接和硬链接，并在使用前比较原始及规范化的 device/inode/link-count 身份；
- 生成的辅助脚本在显示器检测前校验卷根。符号链接、硬链接和非标准位置都会显式退出且不打印
  成功信息。位于另一个有效 `<volume>/Users/<user>/` 布局中的独立复制或移动版本绑定到那个卷，
  而不是绑定进程当前目录；
- 生成的辅助脚本只在路径信任检查通过后调用显示器发现，并从已验证的卷根构造 `restorePath`；
- 两个旧入口都只暴露选项 `1`。旧的“全部重置”选项及其递归删除整个 Overrides 根的行为已移除；
- 既有按产品清理保持 fail-closed：变更前置检查会验证 vendor 和 `Icons.plist` 路径；任一精确
  unlink 或 plist 编辑失败都会在打印 `HIDPI Disabled` 前退出。

## 回归覆盖

`tests/test_intel_hidpi_legacy_cleanup.sh` 在隔离临时卷中验证所有路径：

- 从诱导性的工作目录直接运行恢复辅助脚本时，只删除其自身卷中的选定产品，保留同 vendor
  sibling 和当前目录诱导文件；
- 硬链接、符号链接和非标准辅助脚本位置在清理前被拒绝，选定目标和 sibling 保持不变；位于
  第二个有效卷布局下的独立复制版本只影响第二个卷；
- 旧菜单和生成的辅助脚本都拒绝选项 `2`，不打印成功信息，也不执行删除；
- 产品条目为目录时，精确 unlink 失败，目录和 sibling 保留且不打印成功信息；
- 已有 `Icons.plist`、vendor 链接、附件链接、硬链接和替换竞态仍按预期拒绝或限制在选定产品。

测试还会检查辅助脚本源码：不含旧的 `rootPath="../.."` 计算和 `rm -rf`，也不含已移除的重置
命令或菜单标签。

## 自动验证

最终改动后的以下命令均以退出码 0 完成：

```sh
bash -n hidpi.sh tests/test_intel_hidpi_legacy_cleanup.sh
shellcheck -s bash tests/test_intel_hidpi_legacy_cleanup.sh
bash tests/test_intel_hidpi_legacy_cleanup.sh
bash tests/test_intel_hidpi_inventory.sh
bash tests/test_intel_hidpi_preview.sh
bash tests/test_intel_hidpi_apply_revert.sh
bash tests/test_intel_hidpi_menu.sh
bash tests/test_intel_hidpi_root_binding.sh
bash tests/test_intel_hidpi_storage_races.sh
bash tests/test_intel_hidpi_storage_races.sh
git diff --check
```

七个功能套件均报告对应的 `PASS` 行。两次独立的 `storage-races` 重跑都以退出码 0 完成，并
报告 `PASS: Intel HiDPI storage races`。

完整 `hidpi.sh` 的 ShellCheck 调用仍因无关分辨率辅助函数中的五个既有 `SC2068` 诊断而返回
非零。基线 `HEAD` 具有相同的五个 `SC2068` 和相同的规则集合；本任务没有新增诊断。变更的
旧版清理测试通过 ShellCheck。

## 自审与剩余边界

- `git diff --check` 通过，任务 diff 仅限恢复实现、聚焦回归 fixture、两份恢复说明、本记录和
  IH-015 任务状态；
- 删除路径仍限定为 `DisplayProductID-<id>`、`.icns` 和 `.tiff`，有意保留空 vendor 目录，避免
  按路径删除目录时产生竞态；
- 拥有修改辅助脚本父目录或受保护系统 Overrides 树权限的非协作进程，仍可在独立系统调用之间
  竞争。实现会在使用前绑定辅助脚本身份，用 descriptor-bound `openat` 和 `O_NOFOLLOW` 清理，
  在路径不安全时 fail-closed，但无法把等价系统权限攻击者下的操作表示为绝对事务；
- IH-005 已作为获授权的 Lenovo 回退验证记录完成。真实 Intel 外接显示器启用、重启、睡眠、
  热插拔以及任何后续真实 apply 或 revert 永久禁止，且本任务未尝试执行。
